What each link carries

LinkCredential
Browser → its WorkerEncrypted __Host-hf_session cookie. HttpOnly, host-only, SameSite=Lax.
Worker → RailsAuthorization: Bearer WorkOS access token, plus Hydraflow-Organization, Hydraflow-Client-IP and Hydraflow-Worker-Secret, all set by the Worker.
Worker ↔ WorkOSAPI key (Worker secret). Code exchange, refresh, organization switch.
Mobile → RailsAuthorization: Bearer from PKCE sign-in, plus Hydraflow-Organization.
WorkOS → RailsSigned webhooks. Rails verifies them and syncs idempotently.

Never

  • The browser never sees the access token or calls Rails.
  • Rails never sets cookies. It verifies Bearer tokens against the WorkOS JWKS.
  • Rails never reads host headers, and the gym slug never grants access. Rails always checks the staff membership or the Member.
  • Workers hold no business rules and touch no database.
